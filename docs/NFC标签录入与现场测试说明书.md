# NFC 标签录入与现场测试说明书

本文只负责第一版局域网 MVP 的“标签录入 + 网页闭环测试”：把玩家名牌和任务点的网址写入普通 NTAG213 标签，并用 iPhone 或安卓手机测试击杀、任务、冷却及裁判确认。它不是完整游戏规则或现场运营手册。

## 1. 先记住最重要的规则

每张标签只写入一个完整的 URL，网址必须从裁判台复制，不要自己拼随机令牌。

| 标签贴在哪里 | 应写入的网址格式 | 碰触后做什么 |
|---|---|---|
| 某位玩家的名牌 | `http://电脑局域网IP:3000/nfc/player/<随机令牌>` | 把这位玩家识别为击杀目标 |
| 某个固定任务点 | `http://电脑局域网IP:3000/nfc/task/<随机令牌>` | 打开这个任务点的开始页面 |

不要写入以下内容：

- `localhost` 或 `127.0.0.1`：它们在手机上表示手机自己，不是运行服务的电脑；
- 玩家姓名、阵营、角色、数据库编号或 NFC 芯片 UID；
- `/admin`、裁判 PIN 或任何管理权限；
- 单独一段普通文本。写卡 App 中必须选择“网址、URL、URI 或 Link”记录类型。

一张实体标签对应一个网址。写完后应立即在标签背面或保护贴上记录“红鸭名牌”“任务点 A”等用途，避免贴错。

## 2. 测试前准备

### 2.1 首次安装和配置

电脑需要安装 Node.js 24。首次运行时，在项目目录打开 PowerShell：

```powershell
cd D:\Users\Admin\Desktop\实景鹅鸭杀\nfc-mvp
node --version
npm install
if (!(Test-Path .env.local)) { Copy-Item .env.example .env.local }
```

`node --version` 应显示 `v24` 开头。最后一行只会在 `.env.local` 不存在时创建它，不会覆盖已有配置。

打开 `.env.local`，至少检查以下三项：

```dotenv
PUBLIC_BASE_URL=http://192.168.1.20:3000
SESSION_SECRET=replace-with-a-long-random-value
ADMIN_PIN=2468
```

首次测试可以暂用 `2468`；正式现场使用前，应把 `SESSION_SECRET` 改成长随机字符串，并把 `ADMIN_PIN` 改成只有裁判知道的值。不要把它们发给玩家，也不要提交到 Git。

### 2.2 设置手机能访问的网址

电脑和手机必须连接同一个 Wi-Fi。用下面的命令查看电脑当前的 IPv4 地址：

```powershell
ipconfig
```

找到正在使用的“无线局域网适配器”或“以太网”下的 IPv4。例如电脑地址是 `192.168.1.20`，则把 `.env.local` 中的 `PUBLIC_BASE_URL` 设置为：

```dotenv
PUBLIC_BASE_URL=http://192.168.1.20:3000
```

> 本机在 2026-09-12 核验到的地址是 `http://10.123.105.59:3000`，但局域网 IP 可能在换 Wi-Fi 或重启路由器后变化。每次正式测试前都应重新核对，不能把这个示例当作永久地址。

### 2.3 启动网页

配置完成后运行：

```powershell
npm run dev
```

看到 `Ready` 后不要关闭该终端。电脑先打开：

```text
http://localhost:3000
```

再用手机浏览器手动打开 `.env.local` 中的 `PUBLIC_BASE_URL`。只有手机能正常看到“选择你的身份”，才开始写标签。修改 `.env.local` 后必须停止并重新运行 `npm run dev` 才会生效。

如果 Windows 弹出防火墙提示，只允许 Node.js 访问当前的专用网络即可。

## 3. 每个页面测试什么

| 页面 | 进入方式 | 用于测试 |
|---|---|---|
| `/` | 手机打开局域网首页 | 选择这台手机当前代表的玩家身份 |
| `/me` | 选择身份后自动进入，或手动访问 | 查看本人阵营、存活状态、当前阶段和击杀冷却；也可在没有实体标签时进入任务页 |
| `/admin` | 电脑访问并输入裁判 PIN | 切换阶段、查看并手动选中复制 NFC 网址、确认任务、修正状态、查看事件和重置测试局 |
| `/nfc/player/<令牌>` | 碰触玩家名牌，或在浏览器粘贴裁判台网址 | 识别击杀目标并提交“确认击杀” |
| `/nfc/task/<令牌>` | 碰触任务点，或从 `/me` 的无 NFC 测试入口进入 | 开始实体任务并等待裁判确认 |
| `/result` | 提交击杀或任务后自动进入 | 显示本次操作成功或失败的具体原因 |

当前测试数据固定为红鸭、黄鸭、蓝鹅、绿鹅，以及任务点 A、任务点 B。当前 MVP 不会自动刷新页面；执行击杀、任务确认、阶段切换或状态修正后，需要在相关手机页面和裁判台手动刷新查看最新状态。

> “重置本局”目前点击后立即执行，没有二次确认且不可撤销。它会清空旧事件、待确认任务和冷却，恢复全部玩家存活，并把阶段改回“准备”；现有 NFC 网址和手机浏览器中已选择的身份会保留。

## 4. 从哪里复制标签网址

1. 电脑打开 `http://localhost:3000/admin`。
2. 输入裁判 PIN。默认测试 PIN 为 `2468`，以 `.env.local` 的实际设置为准。
3. 在“玩家与名牌 URL”表格中找到对应玩家，用鼠标选中这一行显示的完整 NFC 地址，然后按 `Ctrl+C` 复制。
4. 在“任务点 NFC 地址”中，同样手动选中并复制任务点 A 或任务点 B 的完整地址。当前裁判台没有单独的“复制”按钮。
5. 检查网址开头必须是电脑局域网 IP，不能是 `localhost`，也不能显示“电脑局域网IP”占位文字。

玩家 URL 和任务 URL 都包含不可猜测的随机令牌。不要只复制前半段，也不要把一位玩家的网址写到另一位玩家的名牌上。

建议写卡前先做一张对应表：

| 实体标签编号 | 实体用途 | 从裁判台复制的网址 | 写入后已复测 |
|---|---|---|---|
| 01 | 红鸭名牌 | 完整玩家 URL | □ |
| 02 | 蓝鹅名牌 | 完整玩家 URL | □ |
| 03 | 任务点 A | 完整任务 URL | □ |

## 5. 把网址写入 NTAG213

第一批标签建议使用空白、未锁定的 NTAG213。不要启用密码保护，也不要设为永久只读，因为电脑 IP 变化后可能需要重写。

以安卓手机上的 NXP TagWriter 为例，不同版本的菜单文字可能略有差异：

1. 打开写卡 App，选择新建数据集或新建记录；
2. 记录类型选择 `Link`、`URL` 或 `URI`，不要选择普通文本；
3. 粘贴从裁判台复制的完整网址；
4. 选择写入，按提示把手机 NFC 感应区贴近 NTAG213；
5. 等待 App 明确显示写入成功，再移开手机；
6. 退出写卡界面，用另一台手机读取标签，检查打开的页面和实体对象一致。

如果用其他 NFC 写卡 App，原则相同：建立一条 NDEF URL/URI 记录、粘贴完整网址、写入并重新读取验证。

iPhone 读取时，将手机顶部靠近标签，等待系统显示网址提示，然后点提示打开。当前网页方案不能绕过系统提示，也不会在未打开网页、未点“确认击杀”时自动杀人。

NFC 页面默认只允许在打开后的 120 秒内提交动作。超过时间后不要继续使用旧页面，重新碰触标签并打开即可。

## 6. 不写标签也能先测网页

建议先验证网页逻辑，再消耗时间写实体标签：

1. 手机打开局域网首页并选择玩家身份；
2. 击杀测试：从电脑裁判台复制某位玩家名牌 URL，发送或粘贴到测试手机浏览器；
3. 任务测试：进入手机的 `/me`，在“无 NFC 时的测试入口”中选择任务点；
4. 网页流程正确后，再把同一批网址写入实体标签。

这种方式和碰触 NFC 后进入的是同一个页面。区别只是 NFC 帮手机快速打开了对应网址。

## 7. 完整击杀测试

准备两台手机最直观；只有一台手机时，也可以用“更换身份”反复切换，但不适合测试并发。

1. 确认不需要保留旧测试记录后，电脑进入 `/admin`，点击“重置本局”。该操作会立即清空本局数据。
2. 将阶段切换到“准备”。
3. 手机 A 打开首页，选择红鸭或黄鸭作为坏人。
4. 手机 B 打开首页，选择蓝鹅或绿鹅作为目标。每台手机只选择自己的身份。
5. 裁判把阶段切换到“行动”。
6. 手机 A 碰触手机 B 对应的玩家名牌，点系统网址提示。
7. 页面应显示正确目标、当前操作者和“确认击杀某玩家”按钮。
8. 手机 A 点“确认击杀”。成功页应提示击杀成功。
9. 手动刷新手机 A 的 `/me` 查看 5 分钟击杀冷却；刷新裁判台，确认目标已经死亡，并查看 `KILL_SUCCESS` 事件。

继续验证异常情况：

- 冷却期间再碰另一名存活玩家的名牌，应被冷却阻止；
- 再碰已经死亡玩家的名牌，应提示目标已经死亡；
- 好人手机碰玩家名牌，不能提交有效击杀；
- 裁判切换到“会议”“暂停”或“准备”后，击杀按钮不可用；
- 需要继续测试时，裁判可填写原因并执行“复活”或“清除击杀冷却”。

## 8. 完整任务测试

1. 裁判确认阶段为“行动”，测试玩家仍存活。
2. 玩家手机碰触任务点 A 标签，点系统网址提示。
3. 页面应显示任务点 A、当前玩家、阶段和该玩家对此任务的冷却。
4. 点击“开始任务点 A”，然后在线下完成实体任务。
5. 手动刷新电脑裁判台，“等待确认的任务”中应出现“玩家 · 任务点 A”。
6. 裁判点击“确认完成”，该玩家对任务点 A 开始 3 分钟个人冷却；刷新手机页面后查看最新状态。
7. 同一玩家立即再次碰任务点 A，应被冷却阻止。
8. 换另一位存活玩家碰任务点 A，应仍可正常开始，因为任务冷却按“玩家 + 任务点”分别计算。

如果裁判点击“驳回”，本次任务会记录为已驳回，但不会开始 3 分钟冷却。死亡玩家、非行动阶段玩家或已有同一待确认任务的玩家不能再次开始该任务。

## 9. 常见问题

### 手机打不开网址

依次检查：

1. 标签里是否错误写成 `localhost`；
2. 电脑上的 `npm run dev` 是否仍在运行；
3. 手机与电脑是否在同一个 Wi-Fi；
4. 手机能否手动打开 `http://电脑IPv4:3000`；
5. Windows 防火墙是否允许当前专用网络访问；
6. Wi-Fi 是否开启“客户端隔离”；
7. 电脑 IPv4 是否已经变化。

### 裁判台显示“电脑局域网IP”

说明 `.env.local` 中没有正确设置 `PUBLIC_BASE_URL`，或修改后没有重启开发服务器。设置为实际局域网地址并重新运行 `npm run dev`。

### 能读到标签，但没有作为网址打开

通常是写成了纯文本记录。清空或覆盖标签，重新选择 NDEF URL/URI/Link 类型写入。

### 页面显示的操作者不对

进入 `/me`，点击“更换身份”，再选择这台手机真正对应的玩家。身份保存在当前浏览器中，不保存在 NFC 标签内。

### 按钮是灰色，或点击后被拒绝

页面会对一部分明显条件直接禁用按钮，例如非行动阶段、操作者已死亡、好人发起击杀、目标已死亡，以及任务冷却尚未结束。

有些条件会在点击提交后才由服务器判断，例如击杀自己、攻击同阵营、击杀冷却中、重复提交同一待确认任务，或页面打开已超过 120 秒。按钮看起来可点并不代表动作一定成功，应以 `/result` 的最终结果为准。页面长时间未刷新时，先刷新或重新碰触标签再试。

### 原来能用，删除数据库后标签失效

`data/goose-duck.sqlite` 被删除后，系统会生成新的随机令牌。旧标签网址会失效，需要从新裁判台重新复制并改写标签。普通“重置本局”不会改变网址。

### 标签贴到金属名牌后难以读取

普通湿标贴近金属时可能被干扰。先悬空测试；如果悬空正常、贴上后失效，应改用带隔磁层的抗金属 NFC 标签。

## 10. 一轮测试完成标准

- [ ] 手机可手动打开电脑局域网首页；
- [ ] 每台手机已经选择正确的本人身份；
- [ ] 每张玩家名牌打开正确的玩家目标页；
- [ ] 每张任务标签打开正确的任务点页面；
- [ ] 有效击杀成功，目标死亡且击杀者进入 5 分钟冷却；
- [ ] 冷却、错误阶段、好人击杀和重复击杀均被阻止；
- [ ] 任务可以开始并出现在裁判台待确认列表；
- [ ] 裁判确认后仅该玩家的该任务进入 3 分钟冷却；
- [ ] 裁判台能看到对应事件记录；
- [ ] iPhone 和安卓各至少完成一次真实标签读取。

第一版静态 NFC URL 可以被复制或转发，因此只用于有人监督的现场 MVP 测试，不应把它当作强防作弊或加密身份系统。
