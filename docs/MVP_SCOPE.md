# NFC 网页 MVP 范围与验收

## 1. 验证目标

第一版只回答三个问题：

1. 普通 NTAG213 写入局域网 URL 后，iPhone 与安卓能否可靠打开对应页面；
2. 服务端能否无争议地处理“谁碰了谁、是否击杀成功、何时解除冷却”；
3. 同一种方式能否用于任务点，并正确处理个人重复冷却。

它不是完整线上化游戏，也不是正式防作弊系统。

## 2. NFC 用在哪里

| 实体对象 | 标签内容 | 碰触后的网页动作 | 服务端保存的真相 |
|---|---|---|---|
| 玩家名牌 | `/nfc/player/<随机令牌>` | 显示目标并请求操作者确认击杀 | 标签绑定、操作者、目标、存活状态、冷却和事件 |
| 固定任务点 | `/nfc/task/<随机令牌>` | 显示任务点并允许开始任务 | 任务绑定、参与者、开始/完成状态和个人重复冷却 |

NFC 不用于阶段计时、玩家登录、裁判改状态、事件查询或任务结果判定。这些功能虽然在网页中，但不是 NFC 功能。NFC 的职责仅是把手机带到正确的实体对象页面。

## 3. 第一版必须具备

### 玩家侧

- 通过本局短码或裁判给出的入口选择/确认本人身份；
- 查看本人存活状态、当前阶段和个人击杀/任务冷却；
- 从玩家名牌 NFC URL 打开目标页；
- 明确看到目标编号或昵称，并主动确认提交；
- 获得成功或失败结果及具体原因；
- 从任务点 NFC URL 打开任务页并发起任务；
- 查看任务等待裁判确认、完成或冷却中的状态。

### 裁判侧

- 创建或重置一场测试局；
- 建立玩家及任务点；
- 把随机标签令牌绑定到玩家名牌或任务点；
- 把测试玩家设置为好人、坏人或裁判可见的等价测试权限；
- 切换 `准备/行动/会议/暂停/结束` 阶段；
- 查看当前玩家状态、冷却和按时间排序的事件；
- 确认或驳回实体任务完成；
- 对误操作进行死亡撤销、复活、冷却清除或状态修正，并填写原因。

### 系统侧

- 服务端统一计时；
- 击杀与任务状态以数据库为准；
- 写操作具有幂等性；
- 同一目标的并发击杀只结算一次；
- 阶段不允许时拒绝操作；
- 事件记录可供裁判复核。

## 4. 默认规则参数

以下来自当前规则文档，仍允许现场调整：

| 参数 | MVP 默认值 | 状态 |
|---|---:|---|
| 坏人个人击杀冷却 | 300 秒 | 暂定待测 |
| 同一玩家完成同一任务后的冷却 | 180 秒 | 已确认方向，数值待测 |
| 开场统一保护 | 0 秒，即关闭 | 原规则仍待实测，必须可配置 |
| 任务点数量 | 先建 1—3 个 | 机制测试规模，不代表完整局 |
| 测试人数 | 2—8 人 | 用于分项测试，不代表正式 18 人局 |

冷却是否跨会议和天黑继续计算尚未冻结。MVP 的数据模型必须能支持“自然时间继续”和“阶段暂停/重置”两种策略，但第一轮界面只实现一个经用户确认的策略。

## 5. 明确不做

- 完整投票、天黑和胜利结算；
- 守卫、枪手、禁言长老等完整角色技能；
- 坏人聊天或玩家社交功能；
- 自动判断实体任务是否真的完成；
- 尸体发现、敲钟硬件或定位；
- NFC 密码学认证、动态标签或防复制硬件；
- 原生 iOS/Android App、企业签名或 App Store；
- 微信小程序；
- 公开注册、手机号、支付、排行榜；
- 公网部署和多门店架构。

## 6. 关键流程

### 击杀

```text
坏人已进入本局
  → 碰触目标名牌
  → 系统提示打开 URL
  → 网页显示目标并要求确认
  → 服务端原子校验并结算
  → 成功：目标死亡、坏人进入个人冷却、写事件
  → 失败：不改变状态，并返回可理解的原因
```

### 任务

```text
玩家已进入本局
  → 碰触任务点
  → 网页显示任务说明并开始
  → 玩家在线下完成实体动作
  → 裁判确认结果
  → 成功：写完成事件，并开始该玩家对该任务的个人冷却
```

## 7. MVP 通过标准

只有同时满足以下条件，才算第一版闭环通过：

- 至少一台 iPhone 和一台安卓可从真实 NTAG213 打开局域网页面；
- 两名测试玩家能完成一次有效击杀，目标状态即时可查；
- 冷却中的第二次击杀被拒绝，修改测试时钟后可再次成功；
- 重复点击、刷新和网络重试不会产生两条有效击杀；
- 两名操作者同时击杀同一目标时只有一人成功；
- 玩家能从任务标签发起任务，裁判确认后进入 3 分钟个人冷却；
- 另一个玩家可以立即挑战同一任务；
- 会议或暂停阶段的击杀与任务被正确拒绝；
- 裁判能看到完整事件链并对测试误操作进行有原因的修正；
- 手机页面在常见竖屏宽度下无需横向滚动即可完成关键操作。

## 8. 第一轮实现采用的暂定决策

1. SQLite 驱动使用 Node.js 24 自带的 `node:sqlite`，接受当前实验性功能警告；
2. 击杀页只设置一次明确确认按钮，不增加额外倒计时；
3. 冷却按自然时间继续，不因会议或暂停冻结；
4. 玩家本人从测试玩家列表中选择，身份写入签名 Cookie；
5. 任务完成由裁判台统一确认。

这些决定用于最小测试，不代表完整玩法已经冻结。
